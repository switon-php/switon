# 设计说明 {#design-rationale}

`switon/principal` 标准化**已解析**的身份与租户状态，**不**拥有认证或租户发现。

## 参见 {#see-also}

- [Principal 包](README.md) — 用法、概念与边界
- [Principal FAQ](faq.md#principal-faq) — 短答与状态相关问题

---

## 要解决的问题 {#core-problem}

多数应用代码不关心调用方**如何**认证或租户**如何**找到，只关心**解析结果**：

- 当前调用方是谁；
- 调用方是否已认证；
- 有哪些可用角色；
- 当前是否已解析租户；
- 哪一个租户 id 或 code 限定工作范围。

若无共享契约，这些事实会散落在会话、令牌、头、请求特性或应用专有数组中；同一概念在不同位置形态不一。

## 为何需要这些契约 {#contracts-exist}

`IdentityInterface` 与 `TenantInterface` 为使用侧代码提供**一种稳定形态**的已解析主体状态。

边界清晰：

- 边界代码负责解析身份或租户；
- 应用代码读规范化的运行时状态；
- 本包不参与认证与发现策略。

## 刻意不拥有 {#outside}

这些契约**不**拥有：

- 认证协议；
- 租户发现规则；
- 传输层专有 payload；
- 用户或租户的持久化模型。

范围刻意收窄：契约描述**共享使用边界**，而非背后的来源系统，因而可长期稳定。
