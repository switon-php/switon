# 设计说明 {#design-rationale}

`switon/console` 把终端相关机制挡在 `switon/core` 和写命令的细节之外，让应用共用一套进度与样式层，而不是每个命令重写一遍。

## 核心问题 {#core-problem}

终端输出混合了三类容易揉在一起的关注点：原地进度、宽度探测与 ANSI 样式。若每条命令在方法里各实现一套，输出往往又吵又不一致，也难测。

## 首要目标 {#primary-goal}

暴露小块可复用原语，而不是完整终端工具箱。

- **好处：** 无论调用方是命令、worker 还是测试，应用共用一套进度模型与宽度模型。
- **好处：** 宿主有自己的 `ConsoleInterface` 实现时，原语仍可用。
- **代价：** 本包不替你选应用绑定；集成要显式完成。

## 核心取舍 {#core-choice}

三个相互独立的原语，各管一类事。

- `ProgressBar` 管渲染状态与时间提示；自动启动让调用点保持简短。
- 宽度取自 `COLUMNS` 环境变量，由负责渲染的那一层自己读取，因此没有共享的 detector 服务。
- `Colors` 只管 ANSI 位掩码常量，是纯常量类。

拆开以后，每个原语既容易直接使用，也容易在应用已有终端层时被替换。

## 取舍 {#trade-off}

`switon/console` 不负责完整命令 UX 或 DI 接线。

- **好处：** 包在 CLI、队列、测试等上下文里都可复用、侵入性低。
- **代价：** 宿主（通常是 `switon/cli`）要接好接口；单靠原语形不成可运行的命令面。

## 刻意保持简单 {#deliberate-simplicity}

优先稳定终端行为，而不是堆功能。

- 进度在需要时启动，结束时留干净换行；
- 宽度探测缓存第一份可用结果；
- 着色保持位掩码，不再单独做主题系统。

这足够覆盖常见终端输出路径，又不会把包做成 UI 框架。
