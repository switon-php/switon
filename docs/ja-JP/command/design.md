# 設計の狙い {#design-rationale}

`switon/command` はコマンド発見とメタデータを **ひとつの共有層** に置き、CLI の help と AI ツーリングが **同じ形** を読むようにします。

## 参照 {#see-also}

- [Command パッケージ](README.md) — 使い方・メタデータ・公開契約
- [FAQ](faq.md) — よくある質問

## 抱えていた問題 {#core-problem}

コマンドまわりはだいたい三方向に散らばりがちです。

- 利用者が独自の発見ルールを増やす
- 別の利用者が help を一から書き直す
- 第三の経路が AI 用注釈を別管理にする

Switon はこれらを **ひとつのメタデータモデル** に置き、作者がコマンドを **一度だけ** 説明するようにします。

## 主な狙い {#primary-goal}

ランナーになる前に、コマンド名・可視性・要約・別名を揃えます。

- **利点:** CLI と Beacon が同じ定義を共有できる。
- **利点:** help とツール用メタがずれにくい。
- **代償:** 実行・スケジューリング・トランスポートはこのパッケージの外。

## 中核の選択 {#core-choice}

クラス名がコマンド族、`*Action()` メソッドがエントリ、属性がオーバーレイです。

- 発見がレジストリを組み立てる
- インスペクションが要約・アクション・パラメータを読む
- `#[Hidden]`、`#[Tool]`、`#[ShortOption]` は飾る宣言に小さく閉じる

パッケージ全体をフルコマンドフレームワークにせず、モデルを読み取りやすく保ちます。

## トレードオフ {#trade-off}

呼び出し・シェル UX・生成カタログはこのパッケージの所有物にしません。

- **利点:** メタデータ層が複数の利用者で再利用できる。
- **利点:** 同じクラスが CLI help と AI ツールの両方に供せる。
- **代償:** 上位のコマンド振る舞いは CLI や関連パッケージ側。

## 意図的な単純さ {#deliberate-simplicity}

安定した執筆面で止めます。

- 発見はキャッシュされたマップを返す
- アクションメタは反射と PHPDoc
- ツール説明は短いのが設計
- 隠しエントリも実行は可能

オペレータ体験全体をこのパッケージに押し込まず、よくあるコマンド執筆経路には十分で、肥大化を避けます。
