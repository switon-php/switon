# 設計の狙い {#design-rationale}

`Dict` が標準化するのは、Switon アプリで繰り返し起きる問題 — 制御された値集合がアクションパラメータ・検証・UI オプション参照のあいだでずれることです。

## なぜ必要か {#why-this-exists}

アプリは制御値の保存方法はだいたい分かっている。ずれるのは **使い方** 側。

- あるコントローラは生スカラーを受け取る
- あるフォームはローカルな options 配列を持つ
- ある入力オブジェクトは別の正規化をする
- ある reader はラベルを独自ヘルパーで出す

`Dict` はまずそのずれを狙う。

## Switon が揃えるもの {#what-switon-standardizes}

次の入口を収束させる:

- 型付きアクションパラメータ
- `DictValue` によるスカラーフィールド検証
- `OptionReaderInterface` による UI オプション参照
- `builtin` フラグによる組み込みとアプリ所有データの分離

ソースが変わっても利用の形は安定したままにする。

## 外に置くもの {#what-stays-outside}

`Dict` は必須スキーマ・管理 UI・組み込み業務コンテンツを定義しない。

それらはアプリまたはアダプタ層に残す。フレームワークは読み取り側契約と、その周りの型付き境界だけを標準化する。
