# 設計の狙い {#design-rationale}

Beacon があるのは、Switon アプリに **バージョン付き** で **アプリ向け** の AI ブートストラップ層を渡すためです。ルールとスキルを、単なるバラバラの PHP ライブラリだけでなく **普通のパッケージと同じように** 配ります。

## Beacon が揃えるもの {#what-beacon-standardizes}

- **ひとつのインストール可能パッケージ:** アプリ向け AI ルールとスキルを同梱して出荷します。
- **ひとつの vendor 位置:** スキルと標準へのポインタは `vendor/switon/beacon/` に置きます。
- **ひとつの更新経路:** Composer のアップグレードで変更が追いやすくなります。

プロジェクトをまたいで「エージェントに何を読ませるか」を共有・更新しやすくなります。

## 意図した境界 {#deliberate-boundaries}

- **アプリ側ルール:** アプリケーションのリポジトリと `AGENTS.md` に残し、`vendor/` 内の Beacon を長期改変しないこと。
- **フレームワーク開発用スキル:** モノレポの `skills/` とコントリビューター向けフローには別置きです。
- **エージェント配線:** IDE やエージェントが Beacon のパスをどう読み込むかは、依然としてアプリが選びます。

その結果、**配布のしかたは揃えつつ**、アプリごとの具体的ルールをすべて同一にする必要はありません。
