# 設計の狙い {#design-rationale}

Switon CLI が標準化するのは、運用コードをスクリプトや別物のコマンドオブジェクトに散らさず、**小さなコマンド形** のまま非 HTTP の手動入口を持つことです。

## 抱えていた問題 {#core-entrypoints-drift}

メンテ・修復・インポート・クリーンアップ・オペレータ向けフローにコマンドが要るのは分かっているが、手動入口がアプリの他から浮いていきがちです。

- ある作業がシェルスクリプトになる
- 別のが独自慣習のコマンドオブジェクトになる
- また別がコンテナや生インフラに直行する
- ツール向けメタが人間向け CLI 面から独立して育つ

Switon CLI は、HTTP・ワーカー・リスナーと **同じアプリの形** の内側に手動入口を置くためにあります。

## 主な狙い {#primary-entry-boundary}

フルワークフローエンジンやツールレジストリになる前に、**手動コマンドがアプリ間で似た見え方になる** ことを優先します。

- **利点:** オペレーションが見つけやすく、レビューや再利用しやすい。
- **代償:** 大規模なコマンドフレームワークやツール専用抽象は既定パッケージの外に残す。
- **効くとき:** 小さな運用コマンドが多く、業務サービスを共有するアプリ。

## コマンド族でありコマンドオブジェクトではない {#command-command-objects}

Switon は **ひとつのクラスをひとつのコマンド族** とみなし、public な `*Action()` を具体エントリにします。

- **利点:** 関連操作を普通の DI でひとクラスにまとめられ、単純なコマンドの儀式が減る。
- **代償:** 無関係なアクションを詰め込みすぎるとクラス境界がぼやける。
- **効くとき:** 小さな運用コマンドが多いアプリ。

## ひとつの公開契約、複数の補助面 {#public-helper-surfaces}

実行の公開契約は小さいまま: `command` または `command:action`。

その周りには補助面があります。

- 空の argv とグローバル `--help` は組み込み `list` へ
- `command --help` と `command:action --help` は組み込み `help` へ
- help では一覧の一貫性のため既定アクションを `command:default` と表示することがある
- 補完はシェル統合に応じてインラインの `command:action` か段階的な候補を出す

- **利点:** オペレータは安定した呼び出し契約を保ちつつ help／補完は使いやすい。
- **代償:** 補助面の見え方が runnable 形とリスト表示で違うことがある。
- **効くとき:** スクリプトの安定と対話 UX の両方を要するチーム。

## レイアウト優先、メタデータは次 {#discovery-layout-metadata}

アプリコードでは発見はまずレイアウトから。`@app/Command/*Command.php` => `App\Command\*Command` や `@app/Areas/*/Command/*Command.php` => `App\Areas\*\Command\*Command` が typical です。

パッケージやツリー外は Composer メタデータ。

- **利点:** よくあるアプリコマンドは軽く、パッケージは安定した登録境界を持てる。
- **代償:** 混在時はファイル配置とメタデータの両方に振る舞いが依存する。
- **効くとき:** vendor のコマンド名を上書きするアプリ。

## 発見と可視性は別 {#visibility-discovery}

発見できても既定の人向け `list` から隠せます。

- **利点:** 既定の `list` が人向けコマンドに集中する。
- **代償:** 隠しと単なる未登録を区別するには `list --all` が要ることがある。
- **効くとき:** 内部／サポート専用 CLI があるプロジェクト。

## AI／ツール向けメタは任意のオーバーレイ {#tool-optional-overlay}

`#[Tool]` はアクションに短い AI／ツール向け説明を付けるだけで、基底 CLI モデルは変えません。

- **利点:** ツール向けメタを増やしても普通の CLI 執筆は変わらない。
- **代償:** `#[Tool]` 単体では完全なツールレジストリ面は提供しない。
- **効くとき:** 人間向け CLI と AI／ツール両方のメタが要るアプリ。

## シェル固有のライブ補完 {#live-specific-integration}

補完は静的な生成レジストリではなく、**現在発見されたコマンド集合とアクション反射** から生成されます。

- **利点:** 補完が今の発見結果と反射されたオプションを反映する。
- **代償:** 振る舞いはシェル側のインストールとキャッシュ状態に依存する。
- **効くとき:** 日々の作業で補完に頼るチーム。

## このパッケージを主役にしないとき {#fit}

リモートジョブランナー、ワークフローエンジン、アプリ全体のツールレジストリが本当に欲しいなら、CLI を実行面に残し、その上に上位パッケージを足してください。

## トレードオフ {#trade-offs}

Switon CLI は、大きな明示的コマンドフレームワークより **頭の中のモデルを小さく** することを選び通常のコマンドのボイラープレートを減らし

- ひとつの安定した公開呼び出し契約
- 発見・可視性・ツールメタの分離

その代わり、作者はコマンドクラスをまとまりよく保ち、PHPDoc を整え、アクションが人向け・隠し・ツール向けのどれかをはっきりさせるべきです。
