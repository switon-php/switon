# Switon mark — v4 brief

Current best direction:

- Use `switon-mark-v4-source.png` as the visual reference.
- Treat this as the preferred concept direction before SVG refinement.

## Why this direction won

- Strong symmetry and a stable central axis
- Clear framework/application relationship
- Diamond-based structure instead of generic AI icon language
- Feels more like a framework symbol than a startup product badge
- Keeps visual tension between outer boundary and inner organized flow

## Meaning

- Outer white structure = the framework
- Inner cyan spine and branches = the application organized inside the framework
- Vertical continuity = support, containment, and structural order
- Horizontal turns = extension points, modules, or flow branching

## What to optimize later

- Convert to a clean SVG master without changing the core concept
- Improve small-size readability
- Refine line weight balance between outer structure and inner spine
- Produce a transparent master asset and a favicon simplification

## Preferred color hierarchy

- Outer framework structure should stay white.
- The diamond-like inner skeleton should move closer to the docs-site primary blue so it aligns with the website brand color.
- Cyan should be reduced to a light accent only, or removed if it weakens hierarchy.
- Reading target: white defines the framework boundary, blue defines the structural skeleton inside it.

## Constraints for future refinement

- Do not change the core silhouette
- Do not replace the diamond language with soft curves
- Do not turn it into generic circuitry
- Keep the framework/outside and application/inside reading intact
